## 논문 3편

### 1. EvalDetectBench: A Benchmark for Measuring Evaluation Awareness in Frontier Language Models

- 출처: Xinning Li, Kemunto Ochwang'i, Aryasomayajula Ram Bharadwaj, Alexandra Souly, Robert Kirk; arXiv:2609.01611v1, `cs.AI`/`cs.CL`; 24쪽 (arXiv 공식 메타데이터 및 PDF, p.1).
- 원문: [arXiv 공식 페이지](https://arxiv.org/abs/2609.01611) · [원문 HTML](https://arxiv.org/html/2609.01611) · [원문 PDF](https://arxiv.org/pdf/2609.01611) · [공식 코드](https://github.com/freeze-lasr/aware_bench) · [데이터셋](https://huggingface.co/datasets/el7982/aware-bench/)

#### 핵심 요약

`EvalDetectBench`는 frontier large language model(LLM)이 자신이 평가 중인지와 실제 배포 중인지 구분하는 evaluation awareness를 측정하는 공개 파이프라인·벤치마크다. 논문은 평가와 배포 transcript를 judge model에 제시하고, probe question(PQ)에 대한 이진 응답을 집계해 $P(\text{eval})$과 AUROC를 계산한다 (Abstract; §3, Eq. 1, pp.1, 3).

배포 transcript를 생성한 모델의 정체성이 $P(\text{eval})$ 분산의 11.25%를 설명했고, 모델 하나에 맞춘 고정 PQ가 다른 모델에서는 awareness를 최대 0.08 AUROC만큼 덜 끌어낼 수 있었다. 저자는 모델별 PQ calibration과 generator별 stratified harmonisation을 제안한다 (Abstract; §3.2–3.3, pp.1, 4–7; Figure 5).

평가는 12개 judge model과 13개 benchmark를 대상으로 했고, mixed deployment pool에서 AUROC가 0.76–0.89 범위였다. 논문은 이 결과를 frontier model이 평가와 배포를 무작위 수준보다 잘 구분한다는 근거로 제시한다 (§4, Figure 6, pp.7–8).

#### 중요한 이유

모델 성능·안전성 평가가 모델의 “평가를 알아차리는 능력”에 의해 체계적으로 편향될 수 있음을, PQ 선택과 transcript 생성자 효과로 분해해 보여준다. 특히 평가 결과의 차이가 모델 능력 차이인지 측정 설계 차이인지 분리해야 한다는 실무적 문제를 제기한다 (§3.2–3.3; §5, pp.3–7, 9–10).

#### 한계

이 방법은 모델에게 평가 여부를 직접 묻기 때문에 priming 효과와 정직한 보고 가정에 의존한다. priming이 평가·배포 transcript에 동일하게 작용하지 않으면 AUROC에도 편향이 남을 수 있으며, 이 연구는 평가 pool이 실제 특정 제공자의 트래픽 분포를 대표한다고 보장하지 않는다 (§5, pp.9–10). 따라서 이 벤치마크의 AUROC를 실제 배포에서의 자발적 evaluation awareness와 동일시할 수 없다 `[추론]`.

### 2. The Memory Trust Gap: Capability-Dependent Failures in Persistent-Memory Agents

- 출처: Jundong Hu, Shekar Ramachandran; arXiv:2609.01852v1, `cs.AI`; 14쪽 (arXiv 공식 메타데이터 및 PDF, p.1).
- 원문: [arXiv 공식 페이지](https://arxiv.org/abs/2609.01852) · [원문 HTML](https://arxiv.org/html/2609.01852) · [원문 PDF](https://arxiv.org/pdf/2609.01852)

#### 핵심 요약

이 논문은 persistent memory에 저장된 낡은 사실(stale fact)이 현재의 권위 있는 정보보다 우선되는 현상을 측정한다. 저자는 “메모리가 없으면 풀 수 없는” Benefit suite와 authoritative tool이 정답을 제공하는 Safety suite를 분리하고, `Qwen3` 0.6B/1.7B/4B/8B 모델을 고정된 action-scored benchmark에서 비교한다 (Abstract; §3.1–3.3, pp.1, 3–4).

Benefit suite에서 stale-value reliance는 네 모델 크기에서 0.92/0.99/1.00/1.00이었고, no-memory 대비 정확도 차이 $\Delta_{\mathrm{mem}}$는 −0.33/−0.35/−0.35/−0.37이었다. Safety suite의 trap sweep에서는 8B 모델이 가장 높은 trap level에서 stale-value reliance 1.00과 $\Delta_{\mathrm{mem}}$ −1.00을 보였다 (§4.1, Table 2; §4.2, Table 3, pp.4–6).

저자는 label 제거, stale note의 날짜를 더 최신으로 보이게 하기, source authority, position을 각각 조작한 $2\times2\times2\times2$ factorial을 수행했다. recency 효과는 큰 모델에서 더 강했고(8B−0.6B 차이 +0.302), position 효과는 모델 크기에 따라 부호가 바뀌었다(8B−0.6B −0.326). 반면 authority 효과는 약하고 scale-flat이었다 (§5.1–5.2, Tables 5–6, pp.7–8).

#### 중요한 이유

모델 규모가 커지면 stale evidence를 무조건 덜 믿는다는 가정을 반박한다. 더 큰 모델은 날짜 같은 표면 신호를 더 잘 읽을 수 있지만, 그 신호가 잘못된 최신성 단서라면 stale memory를 더 강하게 따를 수 있다 (§5.2–5.3; §8, pp.8, 12). 이는 persistent memory만의 문제가 아니라 검색 결과·문서·이전 메시지의 충돌을 다루는 agent 설계에도 적용될 가능성이 있다는 점을 control experiment가 시사한다 (§7, Table 11, p.11) `[추론]`.

#### 한계

benchmark는 300개 base scenario와 33개 template family로 고정된 합성형 설정이며, action scoring은 exact/regex/canonical match로 수행된다 (§3.1–3.2, pp.3–4). 저자도 feature 조작 결과가 내부 메커니즘을 식별하지 않는다고 명시한다 (§5.1, p.8). 따라서 실제 장기 대화의 비정형 memory write·retrieval·tool failure까지 동일한 크기의 취약성이 나타나는지는 이 논문만으로 확인되지 않는다 `[확인 필요]`.

### 3. Belief-Calibrated Optimization: An Explicit World Model for Agentic Optimization

- 출처: Yuhan Chen, Zhihua Tian, Mahavir Dabas, Charith Peris, Rahul Gupta, Ming Jin, Feiyang Kang, Siyuan Zhang, Nan Wang, Ruoxi Jia; arXiv:2609.01861v1, `cs.AI`; 15쪽 (arXiv 공식 메타데이터 및 PDF, p.1).
- 원문: [arXiv 공식 페이지](https://arxiv.org/abs/2609.01861) · [원문 HTML](https://arxiv.org/html/2609.01861) · [원문 PDF](https://arxiv.org/pdf/2609.01861)

#### 핵심 요약

`Belief-Calibrated Optimization(BCO)`는 LLM coding agent가 agent scaffold를 반복 수정할 때, 각 수정이 환경에 미칠 영향에 대한 belief를 `world_model_calibration.md`라는 지속 문서에 기록하고 결과에 맞춰 갱신하는 방법이다. 각 iteration에서 proposer가 parent와 world model을 보고 edit를 제안하고, 실행 전 예측을 남긴 뒤, 관측 결과와 비교해 belief를 `Add/Revise/Merge/Remove`한다 (§3.1–3.3, Eq. 2–5, pp.3–5; Appendix A, Algorithm 1).

`LongMemEval-s`, `LoCoMo`, `GAIA`, `AppWorld`, `Terminal-Bench 2.0`의 다섯 benchmark에서 vanilla control과 같은 초기 scaffold·target·split·평가 harness·iteration budget을 사용했다. held-out passrate는 BCO가 각각 0.608/0.453/0.495/0.796/0.492, vanilla가 0.533/0.375/0.343/0.766/0.470이었다 (Table 1, §4.1–4.2, pp.6–7).

target model을 바꾸는 실험에서는 `AppWorld`에서 BCO가 전체 372개 task 중 high/medium/low effort에서 각각 99/77/65개를 완료하지 못했다. non-completion을 실패로 계산하면 BCO가 high·medium에서 vanilla보다 낮았고, 모든 scaffold가 완료한 task만 보면 BCO가 각 tier에서 앞섰다 (§4.3, p.8). world model의 내용 효과를 분리한 offline ablation에서는 intact 문서가 none·scrambled보다 upside hit rate(0.538)와 downside precision(0.217)에서 높았지만, 네 optimization run을 독립 단위로 본 sign test의 양측 $p=0.125$였다 (§4.4, Table 2, p.9).

#### 중요한 이유

일반적인 “reflection을 더 남기자”가 아니라, 예측·관측·교정이 가능한 환경 모델을 최적화 루프의 상태로 명시한다. 다섯 benchmark에서의 held-out 개선과 문서 내용 ablation은 persistent state의 형식보다 기록된 belief의 내용이 중요할 가능성을 보여준다 (§4.2, Table 1; §4.4, Table 2) `[추론]`.

#### 한계

world model은 통계적으로 calibrated posterior가 아니라 LLM의 자연어 요약이며, 환경과 target model이 run 안에서 고정된다는 가정에 의존한다 (§7, pp.10–11). matched comparison은 benchmark마다 method별 한 trajectory만 사용했고, 일부 train split은 안정성 screening 뒤 고정했으며, AppWorld target swap에서는 무제한 scratchpad가 context window를 초과했다 (§4.1, §4.3, §7, pp.6, 8, 10–11). 따라서 다양한 target·동적 도구 환경에서의 재현성과 비용은 `[확인 필요]`다.

- 중요한 이유: frontier model 출시는 capability benchmark만이 아니라 cyber capability, agentic misuse, monitorability를 함께 공개·관리해야 하는 단계로 이동했다 `[추론]`. OpenAI도 해당 monitorability 결과가 adversarial evaluation에 크게 기반하며 전체 alignment 평가에서는 더 안전하다고 구분하므로, “안전해졌다” 또는 “모니터링이 무력화됐다”로 단정할 수 없다 `[확인 필요]` (OpenAI, 본문).

- 핵심 요약: NYCPS는 2026–27학년도에 2K–8학년의 student-facing generative AI 사용을 금지하고, 고등학교에서는 승인된 프로그램의 제한적 사용을 허용한다고 밝혔다 (NYC Mayor's Office, 2026-09-02, 본문; NYCPS 정책, 항목 “AI and Screen Time Policy Updates”). 9–12학년에는 두 차례의 45분 AI literacy module을 두고, 5개 pilot을 teacher supervision 아래 운영한다 (NYCPS 정책, “Grades 9–12: Student-Facing AI Limited, Guided Use”). 장애학생·English Language Learners의 assistive technology는 예외이며, 교직원의 instructional planning·operational use는 기존 privacy/security 승인 아래 허용된다 (NYCPS 정책, “Accessibility Commitments”; “How Teachers and School Staff Members May Use AI”).
- 중요한 이유: 학교 현장이 전면 도입/전면 금지의 이분법보다 학년별 제한, 교사 감독, AI literacy, vendor privacy review를 묶은 단계적 거버넌스를 택하는 사례다 `[추론]`. 이 정책은 교육 효과의 최종 결론이 아니라 2026–27학년도 운영과 평가를 위한 moratorium·pilot이므로, 학습 성과나 안전성 개선이 입증됐다고 쓰면 안 된다 `[확인 필요]` (NYCPS 정책, 본문).
