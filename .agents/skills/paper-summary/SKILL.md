# Paper Summary

사용자가 논문 3편의 요약을 요청했을 때, 결과를 파일에만 저장하지 말고 **검색·원문 확인이 끝난 뒤 채팅으로 바로 보여준다**. 기본 산출물은 채팅 요약이며, 파일 저장은 사용자가 별도로 요청한 경우에만 한다.

## 원문 확인

- 각 논문의 공식 출처를 식별한다. arXiv, 학회 proceedings, 저자 프로젝트 페이지 등에서 제목·저자·연도·식별자를 확정하고 원문 링크를 붙인다.
- 가능하면 저장소의 `papers/`에 있는 PDF를 먼저 읽는다. PDF는 본문·실험·한계를 실제로 확인해야 하며, 초록이나 검색결과만으로 메소드와 결과를 추측하지 않는다. 긴 논문은 본문 → 실험 → 한계/부록 순으로 나누어 읽는다.
- PDF를 읽지 못하고 abstract/HTML만 확인한 경우, 응답 첫머리에 `원문 PDF 미확인`을 명시하고 PDF에서 확인하지 못한 세부사항은 쓰지 않는다.
- 메타데이터와 수치가 출처마다 다르면 공식 원문을 우선하고, 해결되지 않으면 `[확인 필요]`를 붙인다.

## 채팅 출력 형식

세 논문을 각각 다음 네 섹션으로 요약한다. 각 항목에는 공식 출처와 원문 링크를 함께 둔다.

```markdown
## 1. {논문 제목}

- 출처: {저자}; {venue/year}; {arXiv ID 또는 DOI}
- 원문: {공식 PDF/HTML 링크} · 저장소 PDF가 있으면 {상대 경로 링크}

### 초록
논문의 문제·제안·주요 결과를 한국어로 압축한다. 사실마다 `(Abstract)` 또는 해당 위치를 붙인다.

### 전체적인 주장
저자가 무엇을 주장하는지와 그 근거가 무엇인지 구분한다. 주장을 과장하지 말고 핵심 실험·비교를 연결한다. `(§..., Table ..., p....)` 형식을 사용한다.

### 메소드
입력·출력, 모델/모듈 구성, 학습·추론 절차, 손실·평가 설정을 재현 방향이 잡힐 만큼 요약한다. 방법의 각 사실에 원문 위치를 붙인다.

### 한계
저자가 명시한 한계와 내가 원문 결과에서 확인한 한계를 구분한다. 후자는 `[추론]` 또는 `[내 의견]`으로 표시하고, 원문에 없는 설정·수치는 `[확인 필요]`로 남긴다.
```

## 서술 규칙

- 본문은 한국어로 쓰되 논문 제목, 저자명, 모델·데이터셋·지표·전문 용어는 원어를 병기한다. 첫 등장에 `강화학습(reinforcement learning)`처럼 표기하고 이후에는 일관되게 쓴다.
- 모든 수치·성능·데이터셋·하이퍼파라미터·컴퓨트 주장은 `(§..., Table ..., Eq. ..., p....)` 같은 위치 근거와 대응시킨다. 원문에 없는 값은 채우지 않는다.
- “SOTA”, “효율적”, “일반화” 같은 표현은 저자의 홍보 문구로 반복하지 말고 비교 대상·지표·조건을 함께 쓴다.
- 세 논문을 모두 찾고 원문 확인한 뒤 한 번에 채팅으로 제시한다. 논문이 3편보다 적으면 임의로 채우지 말고 부족한 수를 알린다. 3편보다 많으면 사용자가 지정한 논문을 우선하며, 선택 기준을 짧게 밝힌다.
- 논문 간 공통 흐름이나 비교를 덧붙일 때는 개별 논문 사실과 종합적 해석을 구분하고, 종합 해석에는 `[추론]`을 붙인다.
