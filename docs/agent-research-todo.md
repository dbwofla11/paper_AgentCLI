## 작업 대기열

| 작업 ID | 사고실험 경로/ID | 조사 질문 | 상태 | 결과 경로 |
|---|---|---|---|---|
상태: `todo` → `queued` → `running` → `verifying` → `completed`. 실행 오류는 `failed`, 자료 접근이나 입력 부족은 `needs_input`으로 기록한다. `completed`는 검증된 문헌 조사 완료를 뜻하며 아이디어 승인이나 실험 성공을 뜻하지 않는다. 상태 전이는 `python3 .scripts/bin/research_todo.py status <task-id> <status>`로 검사하며, 완료는 지정 결과 파일이 존재해야 한다.

Markdown 표 갱신: `python3 .scripts/bin/research_todo.py render-doc`.

구조화 상태의 정본은 `04-Projects/research-todo/queue.json`이다. 등록된 `queued` 작업은 Orca IDE 실행기를 사용할 수 있다: 먼저 `python3 .scripts/bin/research_todo.py prompts <task-id>`로 컨텍스트를 확인하고, 사용자가 지정한 작업에서 `python3 .scripts/bin/research_todo.py dispatch <task-id> --execute`를 실행한다. 이 명령은 현재 저장소와 Orca worktree 일치, 런타임 준비 상태를 확인한 뒤 세 탐색 역할을 시작하고, 근거 확인 역할을 앞의 세 작업에 의존시킨다. 역할 수를 넘는 동시 실행은 Orca task dependency로 제한한다. 진행 상황은 `python3 .scripts/bin/research_todo.py sync <task-id>`로 해당 Run만 조회한다. 설정한 시간은 `sync` 시 초과가 확인되면 활성 worker 정지를 요청하는 상한이며 주기적 watchdog은 아니다. USD 상한은 Orca가 강제할 수 없어 양수로 설정한 작업의 dispatch를 거부한다. 완료된 네 역할 결과는 자동 승인되지 않는다. `verifying` 뒤 verifier JSON을 점검하고 `publish`와 검증된 `completed` 상태 전환을 수행한다.

## 작업 등록에 필요한 컨텍스트

- 사고실험 ID와 원문 경로, brief 버전 또는 해시
- 핵심 가설, 해결할 문제, 적용 조건과 제약, 반증 조건
- 찾아야 할 기존 솔루션과 비교 질문, 이미 확인한 논문 ID
- 검색 범위와 제외 기준, 조사 예산·시간·병렬 실행 한도
- 결과 저장 위치와 중복 작업 식별자

## 서브에이전트 역할

| 역할 | 조사 내용 | 산출물 |
|---|---|---|
| 기존 솔루션 탐색 | 같은 문제를 푸는 방법, 단순한 baseline, 구현·평가 조건 | 솔루션 후보와 비교표 |
| 레퍼런스 추적 | 후보 방법의 원 논문, 인용·후속 연구, 주장을 뒷받침하는 실험 | 논문 ID·버전·근거 위치 |
| 대안·반대 근거 탐색 | 경쟁 접근, 실패 사례, 가정이 깨지는 조건 | 한계·반대 근거와 적용 조건 |
| 근거 확인 | 앞선 조사 결과의 원문·서지정보·주장 대응 검증 | 확인됨/추론/확인 필요와 사유 |

주 에이전트는 조사 컨텍스트와 역할을 배분하고, 중복 제거·진행 상태·결과 종합을 담당한다. 앞의 세 탐색 역할은 같은 사고실험 컨텍스트를 받아 병렬 조사할 수 있고, 근거 확인 역할은 탐색 결과를 받은 뒤 수행한다. 이 조사 역할은 기존 method/repro/novelty 비판 심사와 구분한다.

## 근거와 결과 규칙

- 검색 질의, 검색일, 실제 검색한 출처, 포함·제외 이유를 기록하고 최소 두 독립 문헌 소스를 확인한다.
- 제목·DOI/arXiv ID·버전과 원문 접근 여부를 확인한다. 검색 요약만 읽은 경우 그 한계를 표시한다.
- 솔루션별로 해결 문제, 핵심 방법, 적용 조건, 기존 대안과의 차이, 관련 논문과 근거 위치를 연결한다.
- 뒷받침하는 근거와 반대·제한 근거를 함께 기록하고, 원문 사실·추론·미확인을 구분한다.
- 기존 논문 JSON의 paper ID와 경로를 재사용한다. 새 논문 저장은 기존 수집 스킬과 스키마를 따른다.
- 결과는 사용자에게 기존 접근과 남은 확인 질문을 보여주는 문헌 조사다. 연구 실행·코드 실험·새로움 확정·아이디어 승인으로 상태를 자동 전환하지 않는다.
