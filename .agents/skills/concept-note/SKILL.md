# Concept Note

사용자가 요청한 개념 또는 검토 완료한 Inbox 후보를 논문·리뷰·실험 자료와 연결해 `02-Concepts/` 공부노트로 만든다. 개념 노트는 논문 요약이 아니라 이해를 축적하는 문서다.

## 적용 조건

- 사용자가 개념 노트 생성, 수정, 통합, 설명 보강을 요청했을 때만 사용한다.
- Inbox 개념 후보는 자동 생성될 수 있지만 학습 정본이 아니다. `02-Concepts/`로 옮기려면 사용자가 후보를 검토하고 자신의 설명을 확인·수정한 뒤 명시적으로 승격을 요청해야 한다. 사용자의 이해를 추정해 대신 써 넣지 않는다.
- 논문 검색·리뷰·트리아지만 요청된 경우에는 개념 노트를 만들거나 수정하지 않는다. 필요해 보이면 채팅에서 선택지로 제안만 한다.
- 사용자가 대상 개념을 지정하지 않았다면 다루려는 개념과 범위를 먼저 확인한다.

## 절차

1. `02-Concepts/README.md`와 `90-Templates/study-note-template.md`를 읽는다.
2. 관련 기존 공부노트를 찾아 중복 여부를 확인한다. 업데이트 요청이면 기존 문서를 우선 보강하고, 같은 개념의 새 파일을 중복 생성하지 않는다.
3. 사용자 자료, 관련 논문 JSON, 리뷰, 원문에서 근거를 모은다. Graphify는 관련 자료를 찾는 탐색 보조로만 쓰며, 그래프의 관계를 원문 근거처럼 취급하지 않는다.
4. 템플릿의 정의·필요성·직관·예시/수식·혼동점·연결 자료·확인할 것을 채운다. 논문 사실에는 논문 리뷰/PDF의 위치를 링크하고, 분석자 설명은 사실과 구분한다.
5. 노트를 `02-Concepts/{concept-slug}.md`에 작성하거나 기존 노트를 갱신한다. 상태는 `초안`으로 시작한다. 사용자가 후보에 이해 확인/수정 내용을 남겼으면 그 내용만 반영한다. `내 설명`을 에이전트가 대신 만들지 않는다.
6. 정본 변경 뒤 `python3 .scripts/bin/graphify_sync.py begin --source 02-Concepts/{concept-slug}.md`를 실행하고 Graphify 스킬을 `.` 대상으로 `--update`로 수행한다. 성공 뒤 `graphify_sync.py complete`로 기록한다. 실패하면 `graphify_sync.py fail --message "..."`을 남기고 정본은 유지하며 동기화 pending과 재시도 방법을 알린다.
7. 완료 후 파일 경로, 사용한 근거, 확인이 필요한 부분을 채팅으로 알린다. 사용자가 검토·수정한 사실만 상태를 `공부 중` 또는 `정리 완료`로 바꾼다.

## 경계

- 요청 범위를 넘어 논문 리뷰, 아이디어 심사, 실험 실행으로 확장하지 않는다.
- 근거가 부족한 사실은 채우지 않고 `[확인 필요]`로 남긴다. 원문에서 확인한 사실과 직관을 위한 설명·추론을 구분한다.
- 여러 논문 간 관계는 각 자료의 근거를 확인한다. 제목이나 Graphify 유사성만으로 영향·인용 관계를 단정하지 않는다.
- Graphify 갱신이나 외부 검색이 필요하면 사용 가능한 프로젝트 절차 안에서 수행하고, 갱신 실패·자료 접근 제한을 보고한다.
